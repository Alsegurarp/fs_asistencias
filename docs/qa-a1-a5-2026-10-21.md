## Fallo encontrado y corregido

El formulario de Keycloak cargaba sin estilos: CSS y scripts de `/resources/`
respondían 404. Su registro indicaba que no podía crear
`/opt/keycloak/data/tmp/kc-gzip-cache/do56n`. El proceso usa UID 1000 pero
el tmpfs estaba montado como `root:root`, modo 0755.

Se asignaron UID 1000, GID 0 y modo 0700 a los tmpfs propios de Keycloak,
conservando raíz de sólo lectura, usuario y restricciones de capacidades.
Se recreó únicamente identidad y se comprobaron los recursos HTTP 200.
La nueva prueba en `infra/keycloak/realm.test.mjs` exige CSS y JS reales con
gzip. Pasaron las siete pruebas aisladas de salud/realm, sin omisiones;
ese subconjunto no incluye `password-change.test.mjs`. El cambio obligatorio
se comprobó de extremo a extremo en los casos A4 de esta sesión.

El ensayo Android se amplió para A3-08; construcción, unitarias, lint y APK
aprobaron. La instrumentación terminó `OK: FIXTURE` con código -1.
